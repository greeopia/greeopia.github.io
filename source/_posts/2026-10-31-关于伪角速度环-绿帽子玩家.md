<p>这里通常的 base_speed 是一个固定值，速度决策也是打表差不多（？）；进行运动学解算:</p>
<pre><code class="language-text">v_center = (vL + vR) / 2 = base_speed
Δω = (vR - vL) / b = 2·Δv / b        (b = 轮距)
并且
R = base · b / (2·Δv)  =  (b/2) · (base_speed / maxOutput)
// 咱也不懂，只知道R_min = base_speed / IR_PID.maxOutput
大概抄一下。。。
ω = v/R = v*tan(δ)/L
</code></pre>
<p>等等等等，外环PID maxOutput恒定。。。也就是说"打表"是根据R_min来测算各个待选项吗，这也可以解释不同元素之间为何速度决策会有差异了</p>

<h3 id="延伸视角maxoutput-本质是转向权限">延伸视角：maxOutput 本质是"转向权限"</h3>
<p>Angle_PID（角速度环）已经在 PID.c 里声明了。一旦以后做 IMU + 循迹仲裁（Tasks.c 里的顺序已经暗示了"简易仲裁"的意图），Δv 的来源会在 IR 环和 IMU 环之间切换。</p>
<p>那时 IR_PID.maxOutput 就不只是"限幅"，而是分配给循迹环的转向权限额度：maxOutput = 0.2 意思是"循迹最多只能占用 ±0.2 m/s 的差速，剩下的留给角速度环纠偏"。这个视角下，maxOutput 应该和 Angle_PID.maxOutput 一起做预算分配：</p>
</blockquote>
<blockquote>
<p>|Δv_IR| + |Δv_IMU| ≤ Δv_available ≈ 0.4  (受约束 B/C 限制的物理总预算)</p>
</blockquote>
