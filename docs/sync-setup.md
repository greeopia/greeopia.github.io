## 同步脚本

`tools/sync-posts.js`

- 博客园订阅源 → 获取文章列表 → 抓取全文 → 生成 `.md`。
- **精确去重**：只读取 frontmatter 的 `cnblogs_url`，按博客园用户名、文章类型和完整 postId 匹配。正文引用和 ID 前缀不作为同一文章的依据；匹配多个已有文件时报错，避免任意覆盖。
- **已有文章保护**：保留既有标题、`date`、`slug`、`permalink`，以及用户编辑的 `tags`、`categories` 等元数据；不因统一时区而改名或重写旧日期，避免改变既有 URL 和评论映射。
- **摘要恢复**：已有文章为脚本生成的 RSS 占位时，抓取成功后替换 `<!-- more -->` 后的原文链接占位，保留前面的摘要与手改内容。缺少全文标记但包含本地内容时，保留原内容并追加全文；抓取失败则保留已有文件，下次重试。仅存在 `<!-- more -->` 不代表已有全文。
- **旧文更新**：每次同步都回查 RSS 列表中的文章页，比较提取的正文，不依赖 RSS 的 `updated` 或发布时间。博客园只改正文、RSS 时间不变时也能更新；正文未变化时不重建文章、不重复写文件。已有文件名、标题和其他 frontmatter 继续保留；自动生成的摘要随正文更新，手写摘要和补充说明保留。
- **手改正文保护**：frontmatter 中的 `cnblogs_source_hash` 记录图片本地化前的远端正文，`cnblogs_content_hash` 记录上次写入的本地正文（含摘要）。远端变化时，只有本地正文仍与上次导入一致才自动更新；两边都改过则保留本地文件、在日志中报告文件及原文链接，并将任务标为失败，待核对差异后处理。仅修改本地标题、标签等元数据不影响正文同步。哈希仅统一 CRLF/LF 和首尾空白，不折叠代码内部空白。
- **旧文首次接入**：缺少同步记录时，只有本地导入正文与远端一致才自动建立基线；不一致（包括旧的本地图片路径与远端地址不同）则保留原文件并提示核对，避免将旧的本地编辑覆盖。本次已核对并为现有 RSS 内的 11 篇文章建立基线；以后不要随意删除或手改这两个哈希字段。
- **检查范围**：RSS 仅提供待检查的文章列表；已退出 RSS 的旧文不会自动回查。同一个图片 URL 的文件内容被替换时，也不会仅凭正文哈希检测出来。
- **新文章命名和日期**：新文件采用 `YYYY-MM-DD-<postId>-<标题片段>.md`，避免不同 postId 的同名文章互相覆盖。文件名日期和新 frontmatter 日期均按固定 `Asia/Shanghai` 时区生成；标题、标签和 URL 等使用安全的 YAML 字符串表示。
- **真实更新时间**：博客园文章从文章页的 `BlogPosting` / `Article` 结构化数据读取 `dateModified`，按北京时间写入 `updated`；即使正文未变，也可补齐缺失的时间，后续相同时间不重复写入。缺少有效修改时间时，旧文章保留已知的 `updated`，新文章回退到发布日期，不用抓取、图片下载或部署当天充当修改时间。本次已从原文恢复现有 12 篇博客园文章的时间，正文和原发布日期保持不变。
- **其他文章的日期**：站点使用 `updated_option: 'date'`，缺少 `updated` 时回退到原 `date`，避免 GitHub checkout 刷新文件时间后所有文章都显示刚更新。其余 3 篇未查到可信的原平台修改记录，采用发布日期回退；Git 导入或仅改标签的提交日不作为正文修改日。直接编辑本地文章后，如需显示新的更新时间，请同时填写头部的 `updated`；新文章模板已包含该字段。
- **图片本地化**：下载到 `source/images/cnblogs/`，成功后把 `<img src>` 改写为 `/images/cnblogs/<图片文件名>`。

图片处理规则：

- 新图片名包含 postId、原文件名主体和 URL 哈希；哈希区分来源、路径和查询参数，避免不同目录的同名图片共用错误缓存。
- 下载时检查 HTTP 状态、响应类型和图片内容签名，拒绝把返回的 HTML 页面当作图片缓存；无扩展名的地址可根据内容识别图片格式。
- 图片先写入同目录临时文件，再原子重命名为目标文件，避免留下半文件；已有缓存也经过有效性检查。
- 同一 URL 的下载去重，但会替换所有对应的图片引用，包括 `alt`、`class` 不同的多个标签；懒加载图片会使用实际图片地址。
- 远端正文未变化时，已有全文残留远程图片仍会重试本地化。已存在的本地引用保持原路径，不强制改为新命名。
- 某张图片下载或校验失败时保留原远程地址，下次同步可重试；不会因此用 RSS 摘要覆盖已有全文。图片重试仅在正文未被本地手改时推进本地哈希基线。

失败按受影响的文章计数，继续处理后续文章；正文抓取失败、图片下载失败或正文冲突时，命令以非零状态退出。新文章仍可保存为下次可重试的 RSS 占位；已有文章抓取失败时保留已有正文，仍可独立重试其中的远程图片；部分图片失败时保留远程引用和其他成功结果。

## GitHub Actions 自动化

- `sync-posts.yml`：定时拉取 → 检测变更 → 提交并推送 → 触发部署
- 变更检测使用 `git status --porcelain`（而非 `git diff`），
  这样**新建的未跟踪文章和图片也能被检测到**并提交
- 提交内容：`source/_posts/` + `source/images/`
- 同步前运行离线回归测试。同步部分失败时，先保存并部署已成功的变更，最后将任务标记为失败，便于发现问题并在下次重试。

## 离线测试与真实同步

使用 Node.js 22.12+。离线回归测试使用临时文件和模拟下载，不访问真实博客园或下载远程图片，也不会修改已有文章：

```powershell
npm test
```

下面的命令是**真实联网同步**，会请求订阅源、文章和图片，并可能写入 `source/_posts/` 与 `source/images/cnblogs/`，不属于离线测试：

```powershell
node tools/sync-posts.js
```

运行真实同步前保存本地修改，运行后审阅新增和变更的文章、元数据及图片。本地同步命令本身不会部署站点；GitHub Actions 的提交、推送和部署步骤由工作流配置控制。
